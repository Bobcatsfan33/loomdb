## Phase 1 (ANN) — landed, with divergences recorded honestly

What the plan asked for, and what actually shipped:

- **O(N·log N) build — done, and proven.** Divergence: measured on a *new* bench
  (`crates/loom-core/tests/hnsw_build_scaling.rs`, geometric 1k→1M with a fitted curve rejecting N²), **not**
  the `ann_amplification` bench at 500/2k/8k/32k, and the old-vs-new curve is not yet published side by
  side. → **folded into Phase 0 as a measurement item (below).**
- **Incremental maintenance off the write path — done** (buffer + fold + union-search). **Divergence that
  matters:** the plan wanted the write path **byte-identical**; it is not. `write_all` now appends each
  indexed vector to an in-branch buffer, under a new per-branch write lock. This was **accepted
  explicitly**: byte-identical was a *means* (protect the AT-045 certification), not an end, and a changed
  write path that is **fully re-certified at `AT045_STRIDE=1`** (done, green — `tests/crash.rs`
  certification log) meets the intent. Measured write-path cost: **~1× baseline** (the buffer append is one
  small entry on the existing ~220 KB commit; `benches/ann_amplification.rs`).
- **Recall oracle over the incremental/union index — done** (`recall_holds_across_the_union_of_graph_and_buffer`).
- **Isolation on the maintenance path — done** (`a_siblings_buffered_vector_is_never_returned`; the fold and
  buffer are in-branch, I-11).
- **ANN default vs opt-in — decided, but NOT yet backed by a number.** The module docs state "scan stays
  the default, ANN is the accelerator." Per guardrail 5, that decision must be read off a measurement.
  → **folded into Phase 0 as a measurement item (below).**

### Phase-0 measurement items (fold-ins, done here or before Phase 2)

1. **Old-vs-new build curve, side by side — DONE** (`crates/loom-branch/tests/build_timing.rs`). The old
   build path was measured by running *the same harness* at the pre-perf parent commit `9126c72` (a git
   worktree — the honest before/after runs the real old code, not a reconstruction), the new build live on
   `main`; both in-memory, clustered, DIM=64, release:

   | N | old µs/insert | new µs/insert | speedup |
   |---|---|---|---|
   | 500 | 5502 | ~60–100 | ~55–90× |
   | 2000 | 7559 | ~125–170 | ~44–60× |
   | 8000 | 26140 | ~100–310 | ~85–260× |

   The **shape** is the proof, not the multiplier: the old per-insert cost **climbs** with N
   (5502 → 7559 → 26140 µs — the per-op-store scatter grows with the tree), while the new cost stays
   **flat** (~100–340 µs across 500 → 32000, matching the ~190 µs/insert the RAM-only build holds to 1M in
   `hnsw_build_scaling`). Flat-vs-climbing *is* "construction came off the per-op store." The 8k old build
   takes ~3.5 min; that is why the old column stops at 8k (its own cost is the evidence). A tripwire in the
   test fails if the new build ever regresses back above 2000 µs/insert. **Honest note:** a first 32k
   sample read 7162 µs/insert; it was CPU contention from a concurrent run, and a clean re-measure gave
   155 µs/insert — the end-to-end build shows **no** store-side superlinearity through 32k (the single bulk
   commit is not the per-commit ref rewrite Phase 2 addresses).
2. **ANN-vs-scan retrieval latency — DONE** (`crates/loom-branch/benches/ann_vs_scan.rs`). Building the
   bench first required the exact scan to *exist* as an API — the docs promised it as a fallback but no
   method returned it — so `Loom::search_scan` was added (exact top-k by scoring every index entry;
   correct-by-construction, pinned by `search_scan_returns_the_exact_top_k` in `tests/ann.rs`). Measured
   query latency, in-memory, DIM=64, k=10, clustered:

   | N | scan med/p95 (ms) | ann med/p95 (ms) | faster |
   |---|---|---|---|
   | 1 000 | 2.6 / 3.5 | 15.5 / 19.3 | scan (6×) |
   | 10 000 | 29.3 / 43.4 | 53.3 / 70.7 | scan (2×) |
   | 50 000 | 161.4 / 227.8 | 63.0 / 80.5 | **ann (2.6×)** |

   **Decision (guardrail 5) — refined, not flipped.** The crossover is **~20 k indexed vectors** (in-memory,
   DIM=64): below it the exact scan is faster *and* exact, so it stays the better default; above it the ANN
   accelerator wins and the gap widens (scan is linear). "ANN whenever an index exists" would be the wrong
   default — at 1 k it is 6× slower than scanning. Two honest bounds, both recorded in `ann.rs`: this is
   **in-memory** (the conservative case for ANN — on object storage the scan's O(N) page reads move the
   crossover *left*, a structural argument not a measured number here); and the engine **does not
   auto-route** — it exposes both paths + the crossover, leaving an automatic size-based router (new
   behavior, own oracle) to a later phase. So the earlier "scan is the default, ANN is the accelerator"
   framing is **vindicated for small/medium branches and made precise with a threshold**, not overturned.

## Phase 2 — refs past O(branches) *(the next deep work; gated on approval)*

The remaining POC-killer. Replace the full-file ref rewrite with a scalable form (log-structured append +
periodic compaction, **or** per-ref objects), **chosen by a bench at 10 / 1k / 100k branches, published.**

- **I-8 holds in the new form:** the manifest is durable before the ref that points at it; ref compaction is
  crash-safe.
- **Re-drive AT-045 `STRIDE=1`** over the new ref store, through a workload that **includes a ref
  compaction** — the write path/ref store changes, so guardrail 2 applies (now demonstrably load-bearing).
- **Recovery time at 100k branches measured and documented.**

## Phases 3–5 — in plan order, each gated

- **Phase 3 (operational basics, the day-one probes):** tested backup/restore (consistent snapshot of pool
  + refs; a mid-write-storm backup restores to a consistent prefix, reusing the AT-045 machinery's spirit);
  `loomctl` (read-only by default: inspect refs/DAG, a record's provenance chain, `taint(S)` dry-run,
  integrity verify; writes require a token); OpenTelemetry metrics + tracing behind a feature flag, **zero
  overhead when disabled, measured.**
- **Phase 4 (keys, from opt-in to a story):** actor-key rotation (old key verifies old writes, new key
  signs new ones; provenance stays verifiable across rotation) and revocation (post-revocation writes
  rejected, pre-revocation writes stay valid and queryable — bitemporal, incl. a revoked key's historical
  writes feeding a taint query); `docs/key-management.md` (Vault/KMS sketch, rotation cadence, compromise
  runbook); `threat-model.md` updated.
- **Phase 5 (the demo that sells):** loomd MCP tool coverage of the core verbs with documented JSON schemas
  and a <5-minute quickstart; `examples/incident-demo/` — a real LLM agent (MCP, provider-agnostic, key
  from env) investigates a seeded incident across three hypothesis branches, one planted document poisoned,
  the operator runs `taint()` and the RecallPlan names the already-executed action with its receipt,
  irreversible section first (scripted fallback keeps CI deterministic); `DEMO.md` walkthrough.

## Guardrails (this repo's culture — extended, never diluted)

1. `docs/invariants.md` is law — especially **I-8** (manifest durable before its ref) and **I-11** (an index
   lives IN its branch, never shared). A change made easier by bending an invariant is the wrong change.
2. Any commit touching the write path, ref store, or commit machinery **re-runs `AT045_STRIDE=1`** and says
   so in the commit message. *(Demonstrated load-bearing in v0.4: it closed its own first exception.)*
3. New retrieval/merge/isolation behavior gets a **model oracle or a measured floor**, not example tests.
   Approximate structures publish their measured error.
4. **Structural security only:** no `WHERE tenant=` filtering, no existence oracles (refusals byte-identical),
   capability tokens carry authority inside the signature, agents propose-and-never-execute.
5. **Decisions are read off measurements, not asserted.** If a choice depends on a number, build the bench
   first (`ann_amplification` is the pattern; the ANN-vs-scan number above is the next instance).
6. README Known-limits stays honest: retire → off the list, discover → on the list, same commit.
7. `fmt` + `clippy -D warnings` + full workspace green before every commit; small commits, narrative style.
